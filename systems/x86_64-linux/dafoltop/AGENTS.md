# dafoltop

A laptop repurposed as the homelab server, running Plasma with autologin and
Niri disabled.

## This host is the live house

home-assistant and the zigbee stack on this box control real lights, heating and
sensors. A unit that fails to start is not an abstract build failure — it is a
dark room.

- Changes to service readiness, ordering or `Type=` get **tested**, not reasoned
  about. A `Type=notify` guess once crash-looped zigbee2mqtt here.
- Deploys need an interactive sudo prompt; a fully unattended `deploy` will
  stall.
- Prefer switching during a window where a rollback is practical.

## Services

home-assistant, ollama (local LLM, also serving norish and karakeep on dafpi),
immich + immich-kiosk, authelia, bookorbit, traefik, lldap, glance, calibre,
grimmory, shelfmark, spliit, streaming, everything-presence-zone-configurator.

Moved to dafpi (2026-10-07/08), relayed by this host's Traefik and served by its
Authelia/lldap: it-tools, papra, donetick, kaneo, sparky-fitness, securo,
kitchenowl, norish, bar-assistant. reactive-resume was removed (unused).

Most are home-manager nps stacks rather than NixOS services — see
[../../../modules/home/services/AGENTS.md](../../../modules/home/services/AGENTS.md)
for what that implies, especially for OIDC.

Home Assistant notification text is generated by a local ollama model
(`qwen2.5:3b` via `ollama-cpu`, `127.0.0.1:11434`, `OLLAMA_KEEP_ALIVE=5m`),
which replaced an OpenAI conversation call.
[../../../flake-modules/services/ollama/README.md](../../../flake-modules/services/ollama/README.md)
documents the one-time HA integration step (config flow, not YAML) and the
`ai_task.generate_data` automation pattern.

## Host-only settings

Sleep, suspend and hibernate targets are disabled, documentation generation is
off, journald is capped at 500M, and `nh` keeps 5 generations / 7 days. None of
these are fleet-wide defaults — do not assume them when editing a shared module.

## Disks and network

Full detail, history and recovery commands: [README.md](README.md). The rules:

- `/`, `/boot`, `/home` stay hand-written in [hardware.nix](hardware.nix); disko
  owns only the two USB disks ([disko.nix](disko.nix) → `/mnt/data`,
  [disko-backup.nix](disko-backup.nix) → `/mnt/backup`). Never adopt the root
  into disko.
- Run disko in **file mode, one file at a time**, `--dry-run` first; flake mode
  acts on every disk.
- Identify disks **by-id, never `sdX`**. Never hot-add, hot-remove or eject a
  drive while the other is in use: the dock drops both.
- After the dock returns, the nine media containers need `reset-failed`, then
  start (README, "Disks").
- `/mnt/backup` also holds dafpi's restic repository; Immich's originals and
  derived data are bind-mounted from two disks (README before touching either).
- **No IPv6 on this host**: every NetworkManager profile sets
  `ipv6.method = disabled`; a new profile reopens an unfiltered hole.
  `ip -6 addr | grep global` must be empty.
- `192.168.0.10` is keyed on the cloned USB-ethernet MAC; do not make blocky the
  global resolver here.
- Readiness of blocky and of the `podman-*` units (sops ordering) is subtle and
  has broken DNS before: read README, "Network identity", before changing it.
