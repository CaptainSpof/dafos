# Home Assistant on dafoltop

This instance runs the actual house. Nothing here is a staging environment.

## API access

The long-lived admin token is a sops secret, `ha-admin-token` in
`secrets/daf/home-assistant.yaml`. The server URL is not secret — it already
appears in several modules.

```bash
export HASS_SERVER=https://home.daftdaf.dev
export HASS_TOKEN=$(sops -d --extract '["ha-admin-token"]' secrets/daf/home-assistant.yaml)
```

Keep it in a command substitution like that so it never lands in a file or the
transcript. The token is admin-equivalent: never echo it, write it into this
repo in plaintext, or put it in a URL query string.

Decryption needs `~/.config/sops/age/keys.txt` or one of daf's user keys, so it
works from any host in the fleet — see
[secrets/AGENTS.md](../../../secrets/AGENTS.md).

This is a _separate_ token from `zone-configurator-ha-token` in
`secrets/daf/everything-presence.yaml`, which belongs to the zone-configurator
service and is not for ad-hoc API calls.

**REST covers states and services:**

```bash
curl -sH "Authorization: Bearer $HASS_TOKEN" "$HASS_SERVER/api/states" | jq -r '.[].entity_id'
curl -sH "Authorization: Bearer $HASS_TOKEN" "$HASS_SERVER/api/states/sensor.foo" | jq
```

**Repairs, the device registry, the entity registry and the area registry are
websocket-only.** There is no REST endpoint for them; reach for `websocat` or
`hass-cli` rather than hunting for one that does not exist.

## Where configuration lives

`modules/nixos/services/home-assistant` holds the declarative half: components,
template sensors, input booleans, automations that are worth
version-controlling. Anything created through the UI lives in the instance's own
storage and will not appear in this repo — check both before concluding
something is not configured.

Frontend cards are packaged in `packages/` (`bubble-card`, `lovelace-*`,
`custom-brand-icons`) and referenced from the module.

## Local LLM

Notification text is generated by a local ollama model rather than OpenAI:
`qwen2.5:3b` on `127.0.0.1:11434` via `ollama-cpu`, `OLLAMA_KEEP_ALIVE=5m`.
Automations call `ai_task.generate_data`. The integration is set up through the
UI config flow, not YAML — the one-time step is documented in
[modules/nixos/services/ollama/README.md](../../../modules/nixos/services/ollama/README.md).

## Presence sensors

Everything Presence zone configuration runs as its own service; see
`modules/nixos/services/everything-presence-zone-configurator/AGENTS.md` for the
OTA and token constraints.

## Deploying

Follow `dafos-rebuild`, with two extra rules:

- **Unit readiness gets tested, not reasoned about.** A `Type=notify` change
  once crash-looped zigbee2mqtt here. If a change touches `Type=`,
  `ExecStartPre`, ordering or readiness, deploy it while watching
  `journalctl -u <unit> -f` and be ready to roll back.
- Deploys to dafoltop need an interactive sudo prompt.

After switching, confirm the instance actually came back:

```bash
curl -sf -H "Authorization: Bearer $HASS_TOKEN" "$HASS_SERVER/api/" | jq
```
